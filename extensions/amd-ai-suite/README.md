# Deployment Tool for AMD Enterprise AI Suite

The Deployment Tool for AMD Enterprise AI Suite is an automated framework designed to streamline the deployment of the AMD AI Suite and provide rapid access to its major components. It operates through a cohesive three-tier architecture comprising a frontend web interface, a backend deployment engine, and a centralized database. Users interact with the frontend to input target Kubernetes Node IPs, password, and IP Pool ranges. These inputs are securely processed by the backend, which leverages Ansible to execute a fully automated, multi-node deployment workflow without requiring manual intervention. All user-submitted data, service locations, and deployment statuses—including error logs—are systematically recorded in the database for future tracking and troubleshooting.

To ensure a smooth deployment, the framework is built to operate on Ubuntu 22.04 or 24.04 and requires an active internet connection to retrieve container images and external resources. It is optimized for environments equipped with AMD MI300X or MI325X GPUs, which are essential for handling model downloads. The target infrastructure must run Kubernetes version 1.33 or higher alongside containerd. During the deployment phase, the tool automatically resolves prerequisites by installing necessary system dependencies—such as Helm, yq, and Kubernetes Python libraries—and dynamically provisions storage configurations. It automatically installs and configures Longhorn or local-path-provisioner to ensure persistent volume availability for the cluster.

The user journey is simplified into a straightforward workflow: operators submit their node details, allow the backend to run the installation scripts, and are seamlessly redirected to the AMD AI Suite web interface upon completion. Following deployment, administrators gain immediate access to a suite of essential services. Core components like AirMui and KC are accessible via predefined default credentials, while administrative credentials and root tokens for infrastructure services such as ArgoCD, Gitea, and OpenBao are securely generated and can be easily retrieved directly from Kubernetes secrets via command-line queries.
